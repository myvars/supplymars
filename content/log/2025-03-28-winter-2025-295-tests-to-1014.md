By the end of 2024 SupplyMars had a catalogue, pricing, orders, purchasing, a simulation and sales reports. It had 295 tests. Before building anything else, I spent the first quarter of 2025 going back over what was there.

## Recipes and Rector

January started with a Rector pass and then housekeeping: eight Symfony Flex recipes updated on 14 January, one commit per recipe, so the config files matched what each package now expects.

## One CRUD handler

The admin screens ran on a generic CRUD layer, in use since February 2024. By January it had six options classes, one per kind of operation plus shared bases. The rewrite collapsed the options into one `CrudOptions` and gave the handlers a single base class with a fixed shape: `process()` checks the entity exists, `setup()` builds that operation's options, and `build()` renders or acts on them. Create, read, update and delete each fill in those steps; search kept its own class.

The same change moved work out of controllers into services, such as `ProductImageCreator`, `ProductImageOrderer` and the supplier product mapping actions.

## A test for every class, twice

The project has had three test tiers since March 2024: unit tests with no kernel, integration tests against a real database through Foundry factories, and application tests that drive the controllers. In the winter I filled them in.

The first step, on 23 January, was entity tests: 262 test methods in a day, written against the entities through their factories. On 13 February the order and purchase order entities moved to [named constructors](/log/orders-built-whole), and their tests and factories moved with them. Then came the big one. Every entity, DTO and event listener, and 42 services outside the CRUD layer, got a unit test, with its collaborators mocked, and an integration test, with the real thing:

| Kind | Unit | Integration |
|------|------|-------------|
| Entities | 24 | 24 |
| Services | 42 | 42 |
| DTOs | 18 | 18 |
| Event listeners | 13 | 13 |

Application tests went from 10 files to 17. The history shows that change as one commit, started on 26 February and finished on 25 March: 494 files, 1,014 test methods at the end of it, up from 597 before it. The same commit moved Rector's configuration to `withComposerBased()`, which picks the Symfony, Doctrine, Twig and PHPUnit rule sets to match the versions installed.

The pairs test different things. `CreateOrderTest` mocks the entity manager, the validator and the event dispatcher, and checks what the service does with them. `CreateOrderIntegrationTest` creates a customer, an address and a VAT rate, runs the service, and finds the order in the database. A unit test says the logic is right; the integration test says it still works once Doctrine, validation and the real entities are involved.

## Smaller fixes

- **`assert()` became real checks.** The custom validation constraints used `assert()` to check what they'd been given. PHP skips `assert()` when assertions are turned off, as production configurations do, so those checks became explicit `InvalidArgumentException`s.
- **Tailwind v4.** `tailwind.config.js` was deleted and the configuration moved into the CSS, with an `@theme` block for the colours. Two custom variants, `turbo-frame:` and `modal:`, let a template style itself differently inside a Turbo Frame or a dialog; 29 templates changed with the upgrade.

*Update, January 2026: the CRUD layer, base class and all, was replaced by FormFlow in [the rebuild by bounded context](/log/rebuilding-by-bounded-context). Its handler swallowed any exception and showed a generic error flash; FormFlow's handlers return a `Result` instead. The test suite was rebuilt with it, per context.*
